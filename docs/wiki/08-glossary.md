# 8 Glossary

Terms used in the code and in this wiki. For the overall picture, see [Overview](01-overview.md).

| Term | Meaning |
|---|---|
| **yt-dlp** | The Python library that extracts video information and downloads streams. The engine imports it as `yt_dlp` and drives it through `YoutubeDL`; it's pinned in `requirements.txt`, built into the .exe, and, when running from source, can be installed from inside the app. |
| **ffmpeg** | External command-line tool yt-dlp uses to merge, remux and convert files. Located by `find_ffmpeg` (the .exe's bundled copy first, then `PATH`) and passed as `ffmpeg_location`. |
| **JavaScript runtime** | deno, node or bun, which yt-dlp needs for YouTube: it runs yt-dlp-ejs, and without it some formats may be missing. `find_js_runtime` picks the .exe's bundled deno, else the first new enough one on `PATH`; jobs and previews pass it to yt-dlp as `js_runtimes`. |
| **yt-dlp-ejs** | YouTube's challenge solver: the script the JavaScript runtime runs. yt-dlp's `default` extra installs it at the version yt-dlp pins; `js_solver_version` reports whether it's there. |
| **Engine** | `download_engine.py`: everything about downloading, without Tk. The window (`youtube_downloader.py`) uses it through callbacks. |
| **DownloadJob** | Downloads one link (a video, playlist or channel) and keeps the result: outcome, counts, error, last file, summary. |
| **DownloadQueue** | Runs one `DownloadJob` per link, in order; a failed link doesn't stop the rest, Cancel skips the remaining ones. One link is a queue of one. |
| **Outcome** | How a job or queue ended: `done`, `failed`, `declined` (a playlist wasn't confirmed) or `canceled`. |
| **Stream** | One downloaded part of a video. "Best MP4" and the resolution choices download separate video and audio streams (`requested_formats`) and merge them. |
| **Merge / remux** | Combining video and audio into one file (`merge_output_format`), or changing the container without re-encoding (`FFmpegVideoRemuxer`). |
| **Format sorting** | yt-dlp's `format_sort` (e.g. `res:720`, `ext:mp4:m4a`): ranks formats by preference instead of filtering them out. |
| **`res:N`** | A sort key limiting the *shorter* side of the video to N, matching YouTube's "720p"-style labels. |
| **`final_ext`** | The extension after conversion (`mp4`, `mp3` or `m4a`), set by `format_opts`. yt-dlp uses it to recognize a converted file that's already there; without it a second run downloads and converts again. |
| **Post-processor (PP)** | A yt-dlp hook with `run(info)`, attached to a stage. A job adds two `CallbackPP`s: `_video_starting` (`before_dl`) and `_file_done` (`after_move`). |
| **`before_dl` / `after_move`** | yt-dlp stages: before a video's streams download, and after its final file is in place. |
| **`__real_download`** | yt-dlp flag in the info dict: `True` when this run actually downloaded the file, `False` when it already existed. |
| **Probe** | `extract_info(url, download=False, process=False)`: finds out what a link points to without processing it, used before asking about a playlist and for previews. |
| **`url` / `url_transparent` / `playlist`** | `_type` values in yt-dlp results: a pointer to another page, a pointer whose fields get merged, or a list of entries (playlist, channel or tab). |
| **Whole playlist** | The checkbox (`playlist_var`). Ticked: download every video from a `watch?v=…&list=…` link without asking. Unticked: only that video, and ask before downloading any playlist or channel. |
| **`ignoreerrors="only_download"`** | yt-dlp option that turns download errors into logged messages instead of exceptions, so one unavailable playlist entry doesn't stop the rest. |
| **Cancel** | Sets an event that the job checks (`_check_canceled`) in the progress hook, before each video and on each of yt-dlp's status messages, raising yt-dlp's `DownloadCancelled`; it also kills a running ffmpeg (`stop_processes`). Then the files this run wrote for the unfinished video are removed, never ones that were already on disk. |
| **Preview** | The thumbnail, title and length shown under the URL box, looked up without downloading (`preview_link`). A newer link, or closing the app, cancels the running lookup. |
| **Main thread / worker** | The Tk thread that owns all widgets, and the daemon threads (started by `_start_worker`, run through `_run_worker`) that do downloads, previews, installs, the JavaScript runtime lookup and the update check. A worker that crashes reports in the log. |
| **`_post`** | Queues a callable for the main thread; the only way workers trigger UI changes besides progress. |
| **Coalesced progress** | `_latest_progress`: one slot the worker overwrites; the main thread shows only its newest value every 50 ms. |
| **Settings file** | JSON with the last folder and format, whether to check for updates, and when it last checked (`settings_path`, `load_settings`, `save_settings`). |
| **Pin** | An exact version in `requirements.txt` (`yt-dlp[default]==…`); the in-app installer uses the same one, Dependabot proposes updates, and a changed yt-dlp pin on `main` releases a new .exe. The ffmpeg and deno builds are pinned separately in `packaging/build_exe.py`, with their checksums. |
| **One-file .exe** | `YT-Downloader.exe`, built by `packaging/build_exe.py` with PyInstaller. It unpacks itself into `sys._MEIPASS` when it starts, where the engine finds the bundled ffmpeg and deno; `sys.frozen` tells the app it's running from it. |
| **Self-check** | `--self-check REPORT`: the app writes what it found (yt-dlp and its pin, ffmpeg, deno, yt-dlp-ejs, yt-dlp's extras, Pillow, whether the window opens) to a JSON file and exits. `build_exe.py --check` runs it on the built .exe and fails if anything is missing. |
| **Update check** | Release .exe only: at most once a day, while "Check for updates at startup" is ticked, it asks api.github.com for the latest release and logs a line if it's newer than the version bundled in the .exe (`app_version`). |
| **Code-signing environment** | The GitHub environment named `code-signing`, which holds what signing needs (the `SIGNPATH_API_TOKEN` secret, the `SIGNPATH_ORGANIZATION_ID` variable) and needs the owner's approval. Only release builds use it, so pull requests are never signed; without the token the .exe stays unsigned. See [Code signing policy](../../README.md#code-signing-policy). |
| **Build provenance attestation** | A signed record, made by the release job, that the .exe was built by this repository's workflow from a given commit. `gh attestation verify YT-Downloader.exe --repo lifeupnorth/YouTubeDownloader` checks it. |
